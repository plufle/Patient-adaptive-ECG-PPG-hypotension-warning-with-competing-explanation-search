## 1. Research aim

> To develop and validate an interpretable cardiovascular digital-twin system that continuously integrates multimodal data — such as ECG, PPG, wearable-sensor, imaging, and clinical measurements — to distinguish normal patient-specific variability from clinically meaningful abnormalities, identify the likely physiological source of the abnormality, and provide an early warning with quantified uncertainty.

**One-sentence novelty claim**

> This project will develop a multimodal, interpretable, uncertainty-aware cardiovascular digital twin that learns individualized normal physiology and detects emerging cardiac abnormalities by combining mechanistic simulation with continuously updated AI inference.

### 1.1 The four novelty pillars

The novelty is the combination of four capabilities in one patient-specific system. Every pillar must be backed by an ablation (see §7.4).

| # | Pillar | What it means in this codebase | Evidence it works |
|---|---|---|---|
| P1 | Patient-specific baseline | Per-patient distribution of physiological parameters, learned in a calibration window and slowly updated | Personalized model beats population thresholds (E3) |
| P2 | Hybrid physiology–AI inference | Mechanistic 0D model + simulation-based inference + neural residual | Hybrid beats pure DL on detection and gives correct source attribution (E1, E4) |
| P3 | Multimodal detection | ECG + PPG fused through cross-signal features (PAT/PTT) and joint inference | Some abnormalities are detected only with fusion (E5) |
| P4 | Explainable, uncertainty-aware alerts | Alert = deviation + mechanism + calibrated uncertainty + trend | Calibrated coverage, low false alarms/hour (E6) |

### 1.2 Scope

| Tier | Modalities | Role |
|---|---|---|
| **Core (must)** | ECG, PPG | Main inputs to the twin |
| **Core (ground truth)** | Arterial blood pressure (ABP) | Used to validate the mechanistic model and to define events; **not** an input at inference time in the "wearable" setting |
| **Secondary** | Clinical covariates (age, sex, BMI, ASA, comorbidities, drugs) | Priors on model parameters; stratification |
| **Secondary** | Wearable accelerometer | Motion-artifact handling and activity context |
| **Future work** | Imaging (echo, MRI) | Discussed in the paper only. Do not build it unless the scope is explicitly changed |

The claim "continuously integrates" is evaluated as **retrospective streaming**: data are replayed in time order and the system only sees the past. State this honestly in the paper.

## 2. Research questions and hypotheses

- **RQ1 (personalization):** Does a patient-specific baseline reduce false alarms at equal sensitivity compared with population thresholds?
  - *H1:* Personalized deviation scores achieve lower false alarms per hour at matched sensitivity for hypotension and arrhythmia events.
- **RQ2 (hybrid inference):** Does coupling a mechanistic model with learned inference improve detection and allow the source to be identified?
  - *H2a:* On synthetic faults with known causes, the hybrid twin attributes the source more accurately than post-hoc explanations of a pure DL model (e.g., SHAP).
  - *H2b:* On real events, the hybrid twin matches or beats pure DL on AUROC with fewer parameters and better calibration.
- **RQ3 (multimodality):** Does ECG+PPG fusion detect abnormalities that single modalities miss?
  - *H3:* Fusion improves early-warning lead time for hypotension, driven mainly by PAT/PTT features.
- **RQ4 (uncertainty):** Are the alerts calibrated?
  - *H4:* Conformal thresholds achieve the nominal coverage (e.g., 90% ± 2%) on held-out patients.

### 3.3 Event definitions (labels)

| Event | Definition | Source |
|---|---|---|
| Hypotension | MAP < 65 mmHg sustained ≥ 1 min | VitalDB, MIMIC ABP |
| Hypertensive surge | MAP > 110 mmHg sustained ≥ 1 min, or a rise of > 20% from the patient's baseline | VitalDB |
| Tachycardia | HR > 100 bpm sustained ≥ 2 min | All |
| AF onset | Rhythm annotation changes to AF | LTAF, MIMIC |
| Arrhythmic beats | Beat annotations (V, S, etc.) | MIT-BIH |

- **Prediction horizons:** 5, 10 and 15 min before event onset.
- **Exclusions:** the first 10 min after induction and any window with an arterial-line flush artifact (flat or square ABP).

### 3.4 Splits

- Splits are **by patient**. A patient never appears in both train and test.
- Ratio 70 / 15 / 15 (train / val / test), with a fixed seed. Save the case-ID lists to `data/splits/*.json` and never regenerate them silently.
- External validation: train on VitalDB, test on MIMIC with no fine-tuning, plus one variant with fine-tuning.

### 3.4a Input specification (what each component receives)

Unit of processing: a **window** of 10 s at 125 Hz, which is 1,250 samples, advanced with a 5 s stride. Every window carries the patient ID and its absolute timestamp.

| Tensor / field | Shape | Content | Normalization | Used by |
|---|---|---|---|---|
| `x_wave` | `[2, 1250]` | Channel 0 = ECG lead II, channel 1 = PPG | Per-window z-score per channel; the raw scale is kept in `x_scale` | [D1] embedding, [D2] residual, pure-DL baselines |
| `x_scale` | `[4]` | Mean and SD of the raw ECG and PPG before normalization | Log for SD | [D1] (PPG amplitude carries physiological information) |
| `x_mask` | `[2, 1250]` | 1 = valid sample, 0 = gap or artifact | — | All; masked samples are ignored in losses |
| `x_feat` | `[F]`, F ≈ 25–35 | Beat-level features from §4.2, aggregated per window (median, IQR) | Standardized with the **training-set** mean and SD | [D1], isolation forest, threshold baselines |
| `x_static` | `[S]`, S ≈ 5–10 | Age, sex, BMI, ASA class, … | Standardized; one-hot for categoricals; missing value → indicator variable | Population prior in [F] |
| `sqi` | `[2]` | Quality score per channel, 0–1 | — | Window filtering; model weighting |
| `t` | scalar | Seconds since the start of recording | — | Streaming, change-point detection, lead time |

**Targets and labels** (never inputs at inference time)

| Field | Shape | Content |
|---|---|---|
| `y_abp` | `[3]` | SBP, DBP and MAP of the window, from invasive ABP |
| `y_abp_wave` | `[1250]` | ABP waveform, for validating the physics fit |
| `y_event_h` | `[3]` | 1 if an event starts within 5, 10 or 15 min after the window ends |
| `y_event_now` | scalar | 1 if the window lies inside an event |
| `theta_true` | `[P]` | True parameters (synthetic data only) |
| `fault_label` | categorical | Injected fault type (synthetic data only) |

**Sequence view for the twin**
- The twin consumes windows **in time order** for each patient: `windows[patient_id]`, sorted by `t`.
- Batching across patients is allowed in training. Streaming evaluation runs one patient at a time with no look-ahead.

**Saved format**
- Parquet for `x_feat`, `x_static`, the labels and metadata.
- Sharded `.npz` (float16) for `x_wave`, `x_mask` and `y_abp_wave`, with one shard per ~50 patients.
- `index.parquet` maps (`patient_id`, `t`) to the shard and row.

**Sanity checks** (run after every dataset build; results in `runs/<id>/data_report.md`)
- Every channel contains no NaNs.
- HR from ECG and HR from PPG agree within 5 bpm in at least 90% of valid windows.
- PAT falls within 100–500 ms.
- The MAP distribution is plausible (40–150 mmHg).
- Event prevalence is reported for each horizon.

## 4. System architecture

```
 Raw ECG/PPG (+ABP for validation)
        │
        ▼
 [A] Preprocessing ── filtering, resampling to 125 Hz, SQI, artifact masking
        │
        ▼
 [B] Feature extraction ── beat-level: RR, HRV, QRS/QT, PPG amplitude/rise time/
        │                   dicrotic notch, PAT (R-peak → PPG foot), PTT proxies
        ▼
 ┌──────────────────────────────┬─────────────────────────────────┐
 │ [C] Mechanistic model        │ [D] Learned components           │
 │ 0D circulation (Windkessel)  │ D1: amortized inference net (SBI)│
 │ + ECG timing model           │ D2: neural residual model        │
 │ params θ = {HR, SV/contract.,│                                  │
 │ R_p, C, Z_c, PTT, ...}       │                                  │
 └──────────────┬───────────────┴──────────────┬──────────────────┘
                └──────────► [E] Hybrid inference ◄┘
                      posterior p(θ_t | x_t) + residual r_t
                                   │
                                   ▼
 [F] Patient baseline ── per-patient distribution of θ and r (calibration window,
                         slow Bayesian/EMA update, frozen during alerts)
                                   │
                                   ▼
 [G] Deviation + change-point ── standardized deviation per parameter,
                                 BOCPD / CUSUM over time
                                   │
                                   ▼
 [H] Alert generator ── conformal threshold → alert with
                        {what changed, mechanism, confidence, trend}
```

### 4.1 [A] Preprocessing

**ECG**
- Band-pass 0.5–40 Hz, then notch at 50/60 Hz.
- R-peak detection with `neurokit2` (`ecg_process`), cross-checked against a second detector.

**PPG**
- Band-pass 0.5–8 Hz.
- Detect the foot with the intersecting-tangent method, plus the systolic peak and the dicrotic notch.

**Common**
- Resample everything to **125 Hz** to match PulseDB/MIMIC.
- Windows are **10 s** with a **5 s** stride, the streaming unit.
- Signal quality: template-matching SQI for both ECG and PPG. A window counts as valid only if **both** pass, except in the single-modality ablations.
- Never interpolate across gaps longer than 2 s. Mask them instead.

### 4.2 [B] Features (beat-level, aggregated per window)

| Group | Features |
|---|---|
| ECG | RR mean/SD, RMSSD, pNN50, QRS width, QT/QTc, ST deviation proxy, R amplitude |
| PPG | Pulse amplitude, rise time, pulse width at 50%, dicrotic notch time/ratio, perfusion index proxy, reflection index |
| Cross-modal (key for P3) | PAT = R-peak → PPG foot; PAT variability; HR agreement between ECG and PPG (catches artifacts) |
| Clinical (static) | Age, sex, BMI, ASA class, baseline drugs (if available) |

### 4.3 [C] Mechanistic model

Start simple. Identifiability matters more than realism.

**Level 1 (default): 3-element Windkessel (WK3)**
- Inflow $Q(t)$: half-sine ejection of stroke volume $SV$ over ejection time $T_{ej}$, repeated every $RR$.
- Equations: $C\,\dot P_p = Q - P_p/R_p$ and $P_{ao} = P_p + Z_c\,Q$.
- Peripheral PPG model: $PPG(t) \propto P_{ao}(t - PTT)$ passed through a first-order low-pass filter $\tau$. This is a **modelling assumption** and must be stated in the paper.
- Parameters: $\theta = \{HR, SV, T_{ej}, R_p, C, Z_c, PTT, \tau\}$. Fit at most ~6 free parameters and fix or derive the rest.

**Level 2 (stretch): closed-loop 0D model**
- Time-varying elastance for the LV, systemic and venous compartments.
- Adds contractility ($E_{max}$) and preload.
- Only attempt it if Level 1 passes the identifiability checks.

**ECG side**
- Use interval and timing features directly.
- For synthetic data, generate ECG with the McSharry dynamical model (`neurokit2.ecg_simulate(method="ecgsyn")`) and control HR, HRV and morphology.

**Implementation**
- Write the simulator in PyTorch (fixed-step RK4 or `torchdiffeq`) so it is vectorized over a batch of parameter sets and runs on the GPU.
- Target speed: at least 10⁵ simulated 10 s windows in under 10 min on a Colab T4.

**Identifiability check (required before step [D])**
- Simulate data with known θ, run inference, and compare the recovered θ with the true θ.
- Report a correlation and a posterior contraction for each parameter.
- If a parameter is not identifiable from ECG+PPG, fix it or merge it with another, and record this in the decision log.

### 4.4 [D] Learned components

**D1: amortized inference (SBI)**
- Library: `sbi` (neural posterior estimation with a normalizing flow).
- Embedding network:
  - A 1D-CNN over the raw ECG and PPG windows (2 channels).
  - It is concatenated with the [B] features and fed to the flow.
- Training data:
  - Simulated (θ, x) pairs from [C], with realistic noise and artifacts added (baseline wander, motion artifact, amplitude scaling).
  - Domain-adaptation step: fine-tune the embedding on real windows, using ABP-derived targets (SV proxy, R_p proxy) where available.
- Output: posterior samples of θ for each window, giving uncertainty for free.

**D2: neural residual model**
- Input: the real window and the waveform simulated from the posterior-mean θ.
- Target: predict the part the physics cannot explain.
- Residual score $r_t$ = reconstruction error of a small conditional autoencoder.
- A high $r_t$ with stable θ means "abnormal pattern not captured by the physiology model". These alerts get the mechanism label "unmodelled / morphology" (e.g., ectopic beats, ST changes).

### 4.5 [E]–[F] Patient baseline (P1)

**Calibration window**
- The first stable 15–30 min, after excluding events and induction.
- For the wearable data, use the first day.

**Baseline**
- Per parameter: a robust mean and spread (median/MAD) of the posterior means, plus the mean posterior width.
- Option: a hierarchical prior, where the population prior is conditioned on clinical covariates and shrinks the patient-level estimate when calibration data are few.

**Update rule**
- Slow EMA update of the baseline, with the half-life set in the config (default 60 min).
- The update is **frozen** while any deviation exceeds the threshold, so an evolving abnormality is not absorbed into the baseline.

### 4.6 [G] Deviation and change-point detection

- **Per-parameter z-score:**
  $z_{k,t} = (\hat\theta_{k,t} - \mu_k)/\sqrt{\sigma_k^2 + s_{k,t}^2}$, where $s_{k,t}$ is the posterior SD. Measurement uncertainty therefore widens the tolerance.
- **Combined score:** Mahalanobis distance over the parameter vector, plus the residual score $r_t$.
- **Temporal layer:** Bayesian online change-point detection (BOCPD) on each parameter trajectory. CUSUM is the simpler baseline.
- **Trend:** slope of θ over the last N windows, reported in each alert.

### 4.7 [H] Alerts and mechanism mapping (P4)

**Threshold**
- Split conformal prediction on the nonconformity score (the combined deviation), calibrated on held-out *normal* windows.
- The target false-alarm rate is set by α (default α = 0.05 per window, then tuned to false alarms per hour).

**Mechanism mapping**
- A rule table maps parameter deviations to physiological interpretations. It lives in `configs/mechanisms.yaml` and must be reviewed by a clinician co-author.

| Dominant deviation | Mechanism label |
|---|---|
| R_p ↑ | Vasoconstriction / increased afterload |
| R_p ↓ | Vasodilation (e.g., anesthesia depth, sepsis-like) |
| C ↓ / PAT ↓ | Arterial stiffening / increased tone |
| SV ↓ with HR ↑ | Hypovolemia / reduced preload |
| SV ↓ with HR stable | Reduced contractility |
| RR irregularity ↑ | Rhythm disturbance (AF-like) |
| QRS/QT change | Conduction / repolarization abnormality |
| r_t ↑ with θ stable | Unmodelled morphology change |

**Alert schema** (JSON, one per alert)
```json
{
  "patient_id": "...", "t_start": 0, "t_alert": 0,
  "score": 0.0, "p_value": 0.0,
  "deviations": [{"param": "R_p", "z": 3.1, "direction": "up", "posterior_sd": 0.2}],
  "mechanism": [{"label": "vasoconstriction", "weight": 0.7}],
  "confidence": 0.0,
  "trend": {"param": "R_p", "slope_per_min": 0.05},
  "modalities_used": ["ecg", "ppg"]
}
```

## 6. Compute and environment

- **Execution:** Google Colab GPU runtimes (T4 by default), used through the **Colab VS Code extension**. Notebooks are edited locally in VS Code and run on the Colab kernel.
- **The Colab kernel cannot see local files.** Local Windows paths (`E:\...`) do not exist on the runtime. All notebook paths go through `dtwin.utils.io`, which resolves to:
  - `/content/drive/MyDrive/dtwin/...` when running on Colab;
  - `./data` and `./runs` when running locally.
- **Getting the code onto Colab:** the repo is pushed to a private GitHub repo. `00_setup_colab.ipynb` runs `git clone` (or `git pull`) followed by `pip install -e .`. Keep the logic in `src/dtwin/` and keep notebooks thin, so the code stays versioned and testable.
- **Session limits:** Colab disconnects on idle and has runtime limits.
  - All training loops save checkpoints to Drive every N steps and resume automatically from the latest checkpoint.
  - Long jobs are split into resumable chunks.
- **Main packages:** `numpy`, `scipy`, `pandas`/`polars`, `torch`, `torchdiffeq`, `sbi`, `neurokit2`, `vitaldb`, `wfdb`, `scikit-learn`, `mapie`, `matplotlib`, `pyyaml`. Pin versions in `pyproject.toml` once the environment works.
- **Reproducibility:**
  - Every run has a `run_id`, the full resolved config saved as YAML, the git commit hash and the seed.
  - Use `dtwin.utils.seed.set_seed` everywhere.

## 7. Experiments

### 7.1 Experiment list

| ID | Question | Setup | Main metrics |
|---|---|---|---|
| **E0** | Is the physics model adequate and identifiable? | Fit WK3 to real ABP/PPG; inference recovery on synthetic data | Waveform RMSE, recovered-vs-true θ correlation, posterior contraction, SBC (simulation-based calibration) |
| **E1** | Can the twin find the *source*? (H2a) | Synthetic patients with injected faults (§7.2) | Source attribution accuracy (top-1/top-2), detection AUROC, detection delay |
| **E2** | Real-event early warning | VitalDB hypotension at 5/10/15 min; MIMIC external | AUROC, AUPRC, sensitivity at fixed false alarms/hour, median lead time |
| **E3** | Does personalization help? (H1) | Twin with vs without patient baseline vs population thresholds | False alarms/hour at matched sensitivity |
| **E4** | Hybrid vs pure DL (H2b) | Same inputs; pure CNN/transformer classifier and autoencoder | AUROC, ECE, parameter count, attribution vs SHAP on E1 |
| **E5** | Does fusion help? (H3) | ECG only / PPG only / ECG+PPG | ΔAUROC, Δlead time; list of events detected only with fusion |
| **E6** | Are alerts calibrated? (H4) | Conformal thresholds on held-out patients | Empirical coverage vs nominal, ECE, alert-rate stability |
| **E7** | Robustness | PPG-DaLiA motion; synthetic noise sweep; missing modality | Performance degradation curves |

### 7.2 Synthetic fault library (for E1)

Each synthetic patient has:
- baseline θ drawn from a population prior;
- realistic slow variability (random walk plus respiratory and Mayer-wave modulation);
- one injected fault with an onset time and a ramp duration (1–30 min).

| Fault | Parameter change | Expected mechanism label |
|---|---|---|
| Vasoconstriction | R_p × 1.3–1.8 | Vasoconstriction |
| Vasodilation | R_p × 0.5–0.8 | Vasodilation |
| Stiffening | C × 0.5–0.8, PTT ↓ | Arterial stiffening |
| Hypovolemia | SV × 0.6–0.8, HR × 1.1–1.4 | Hypovolemia |
| Reduced contractility | SV × 0.6–0.8, T_ej change, HR stable | Reduced contractility |
| AF-like rhythm | RR irregular (high CV), no P-wave (ECG synth) | Rhythm disturbance |
| Morphology (unmodelled) | Ectopic beats / ST shift injected in ECG only | Unmodelled morphology |
| Null | No fault (variability only) | No alert (measures false alarms) |

### 7.3 Baselines

1. **Population thresholds:** fixed limits on HR, MAP proxy, SpO2-like PPG amplitude.
2. **Isolation forest** on the [B] features.
3. **LSTM/Transformer autoencoder** for anomaly detection on raw windows.
4. **Pure supervised DL:** a 1D-CNN over ECG+PPG predicting the event at each horizon.
5. **Published hypotension-prediction approaches** (if reproducible), used for comparison only.
6. **Ablated twins:** see §7.4.

### 7.4 Ablations (one per pillar)

| Ablation | Removes | Supports |
|---|---|---|
| No patient baseline (population prior only) | P1 | H1 |
| No physics (embedding → classifier directly) | P2 | H2 |
| No residual model | Part of P2 | Value of residual for unmodelled events |
| Single modality | P3 | H3 |
| No uncertainty (point estimates, fixed threshold) | P4 | H4 |
| No change-point layer (window-wise only) | Temporal part of P4 | Lead time / stability |

### 7.5 Statistics

- 95% confidence intervals by **patient-level bootstrap** (≥ 1,000 resamples).
- Compare models with paired bootstrap on the same patients, or DeLong for AUROC.
- Report per-subgroup results (age, sex, ASA) to check for failure modes.
- Pre-register the primary metric: **sensitivity at 1 false alarm per hour for 10-min-ahead hypotension**. Do not switch primary metrics after seeing results.

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Novelty overlap with existing digital-twin or hybrid BP work | Finish the related-work table in M0; frame the contribution as the validated *combination* plus source attribution; adjust claims accordingly |
| Parameters not identifiable from ECG+PPG | Identifiability check (E0) before building on top; reduce the parameter set; use clinical priors |
| Sim-to-real gap for the inference network | Realistic noise augmentation; fine-tune on real data with ABP-derived targets; report on real data separately |
| PPG model is a crude approximation | State it as an assumption; validate PAT/PPG against ABP; sensitivity analysis |
| Few real events per patient | Use VitalDB hypotension (frequent); pool events; patient-level bootstrap |
| Colab session limits | Resumable checkpoints; chunked jobs; small models |
| MIMIC access delay | Start with VitalDB; MIMIC is only needed for external validation (M5) |
| Clinical validity of the mechanism table | Clinician co-author reviews `configs/mechanisms.yaml`; label it "likely mechanism", not a diagnosis |

## 11. Working conventions (for Claude and humans)

- **Logic lives in `src/dtwin/`. Notebooks only orchestrate and plot.** If a notebook cell grows past ~20 lines of logic, move it into the package.
- **Configs, not constants.** Thresholds, window sizes, horizons and α are set in `configs/*.yaml`.
- **Paths through `dtwin.utils.io` only.** Never hardcode `E:\`, `C:\` or `/content/...` in package code.
- **No patient leakage.** Any code that touches splits must take the saved split files as input.
- **No look-ahead.** Streaming code may use only data up to time t. Every streaming component should have a test that checks this.
- **Tests:**
  - Physics sanity: positive pressures, MAP ≈ CO × R_p at steady state.
  - Feature extraction on synthetic signals with known HR and PAT.
  - Run `pytest` before committing.
- **Units:** pressure in mmHg, flow in mL/s, time in s, R in mmHg·s/mL, C in mL/mmHg. Document units in docstrings.
- **Results:** every table or figure in the paper must be regenerable from a script plus a config. No hand-edited numbers.
- **Never fabricate results, citations or dataset details.** If something is unverified (e.g., a track name or an API signature), check the docs or the data first, or mark it `TODO(verify)`.
- **Data governance:** never print, upload or commit raw patient-level data from credentialed datasets.
